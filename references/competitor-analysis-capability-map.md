# 竞品广告 SDK 分析能力地图（来自业务汇总）

本文把工作区 `汇总.md` 中的业务目标，**映射并收敛**到本 skill 的执行体系。  
主流程仍是：`SKILL.md` 工具链 + P0–P10 + **8 指标交付** + Playbooks。  
本文不是第二套流程，而是 **「要看清什么 / 对应哪一章 / 证据怎么拿」** 的总表。

**边界：** 可识别并记录竞品的展示/点击/下载/关闭/拉回等**行为与配置**；风控章写检测项、位置、时机、对填充/测量的影响。  
**不**交付生产环境绕过手册、伪造用户或广告欺诈操作步骤。

## 2. 广告生命周期清单（分析时按步勾）

完整链路（与汇总一致，写作时按实际样本裁剪）：

```text
SDK 初始化
  → Init/远程策略配置
  → loadAd（业务→真实请求）
  → 广告数据请求（参数/加密/设备/广告位/频控字段）
  → 响应解析（素材/落地页/下载/deeplink/bid/id…）
  → 广告对象创建与缓存（命中/过期/预加载/重试）
  → show/render（条件、失败原因、模板、容器）
  → 曝光 impression（面积/时长/可见性）
  → 点击 click（区域、坐标、是否自动/模拟——仅识别）
  → 关闭 close（按钮/隐藏/自动关闭）
  → 转化（详情/下载/安装/激活/回流）
  → 事件上报 ad-event（load/show/click/…/error/reward）
  →（可选）策略二次下发
```

**每一步至少记录：**

| 列 | 说明 |
|---|---|
| 方法/类 | jadx 或 so 符号 |
| 数据结构 | 请求/响应/对象字段 |
| 条件 | 何时执行、是否异步、是否走缓存/网络/Native |
| 状态 | hypothesis / confirmed / refuted |
| 证据 | 代码路径 / 动态日志 / env |

有设备时：对 **load→show→impression/click/reward/close** 必须用 clean 最小动态尝试 dispose（见 `dynamic-validation.md`）。

## 3. 策略配置分析清单

### 3.1 配置来源

- Init 下发 JSON  
- 远程 medconfig / OEM 等价物  
- 本地缓存（文件/SP）  
- load/show/click 后的**增量/热更新**策略  

### 3.2 字段类别（建库时用）

| 类 | 例子方向 |
|---|---|
| 开关 | 广告位开关、功能开关、isClosed |
| 频控 | 日上限、间隔、refresh、重试、轮换 |
| 展示 | 模板、尺寸、refreshIn、是否 UI |
| 点击/关闭相关 | 仅记录配置项与代码消费；结合 PB-06 |
| 下载/转化 | 自动下载开关、商店/详情优先级 |
| 风控 | 环境字段、降级开关 |
| 实验 | AB、灰度、实验组 id |
| 收益 | eCPM、bid、floor、waterfall 权重 |

### 3.3 硬规则（来自汇总 + skill）

1. **禁止只靠字段名猜语义** → parser → consumer → 运行变化（bound dict）。  
2. **配置差异**要记维度：设备/地区/新老用户/时间/广告位/SDK 版本（能测多少写多少）。  
3. **配置能力 ≠ 运行胜出** → 强制两行写法（PB-05）。  
4. 动态补充配置：在 load/show/click 后再抓一次配置接口。

## 4. 策略识别清单（行为特征，观测向）

用于指标 2/3：识别竞品是否存在下列**行为模式**（代码 + 动态证据）。  
写作时用「是否存在 / 触发条件 / 证据」，**不**写「如何实现用于上线」。

| 模式 | 静态线索 | 动态线索 |
|---|---|---|
| 异常展示/不可见曝光 | 0 高布局、透明 Activity/Window、异常 bringToFront | 无感曝光、异常 View 层级 |
| 自动/模拟点击 | MotionEvent.obtain、dispatchTouchEvent、performClick 批量构造 | 无真实触摸却 click 上报 |
| 坐标异常 | 点击坐标改写、固定中心点 | 上报坐标与控件不一致 |
| 关闭策略 | skip 隐藏、关闭改下载文案 | PB-06 伪关闭矩阵 |
| 下载策略 | 点击/关闭触发下载 | 落地 market/hap/下载器 |
| 拉回/回流 | moveTaskToFront、REORDER_TASKS、deeplink 回宿主 | 离开后强拉回 |
| 预加载/刷位 | Handler 循环 load、短生命周期插屏 | 关闭后立即再 load |
| 上报异常 | 补报、乱序、改字段 | 事件时序与真实 UI 不符 |
| 二次封装第三方 | 自研壳调穿山甲/GDT/快手… | adapter + 运行 Activity |

命中任一项：写入报告策略章 + `hypotheses[]`，grade 随证据升级。

## 5. 广告元数据与事件（建库模板）

### 5.1 元数据分组

- **广告标识：** adId / creativeId / materialId / campaignId / requestId / bidId / token  
- **广告位：** placement / slot / scene / template / renderType / source  
- **素材：** 图/视频/标题/描述/CTA/落地页/deeplink/下载 URL  
- **设备：** OAID、AndroidId、机型、ROM、系统、网络、运营商…（有则记；敏感字段注意脱敏）  
- **上下文：** Activity、前后台、曝光/点击时间、停留  
- **转化：** 包名、下载状态、安装/激活相关  
- **合规相关：** 隐私弹窗、广告标识、可关闭性  

### 5.2 事件清单

至少覆盖：`load` / `loaded` / `show` / `impression` / `click` / `close` / `download` / `install` / `active` / `reward` / `error`  

每个事件记：时机、字段、条件、是否重试/补报（能证实再写）。

**链路键：** 尽量用 `requestId` / `adId` / `materialId` / `sessionId` 把 请求→对象→展示→点击→上报 串起来。

## 6. 风控与防护矩阵（输出物）

对每个检测项尽量填：

| 检测项 | 层(Java/Native/…) | 时机 | 请求是否携带 | 命中后行为 | 对分析影响 | 状态 | env |
|---|---|---|---|---|---|---|---|

检测项示例（有则写）：Root、Frida、Xposed/LSPosed、Magisk/KernelSU、模拟器、多开/容器、VPN/代理、USB 调试、ptrace、maps 扫描…  

- **定位检测**用 jadx/IDA + 复现（PB-07）。  
- **命中后行为**用 clean 对照再写 confirmed。  
- 矩阵「影响分析」列写：是否导致无配置/无填充/进程退出；**不**写生产 Bypass 步骤。

## 7. 第三方聚合与变现

- 平台清单 + SDK/Adapter 版本 + 混淆/更新线索  
- 聚合形态：自研 / 厂商聚合 / Waterfall / Bidding  
- 流量：优先级、兜底、失败重试、预加载  
- 收益相关字段：eCPM、bid、floor、权重（能拿到再写）  
- 策略与风险：哪些提升展示/点击、哪些有合规风险（观测结论）

Primary 裁决走 **PB-01**，配置 vs 运行走 **PB-05**。

## 8. 竞品基础画像（报告 §0 / inventory 补强）

在 `sdk_inventory` / 报告路径章补充：

1. 厂商、包名、SDK/Adapter 版本、宿主 App、场景与广告位类型  
2. 防护：加固、混淆、字符串加密、动态 Dex、Native 封装  
3. 代码位置：Java / smali / so / 动态 Dex / 插件 / 热更  
4. 敏感权限：网络、标识、下载安装、悬浮窗、REORDER_TASKS 等  
5. 模块：init / 请求 / 渲染 / 点击 / 下载 / 上报 / 风控 / 聚合

1. 仍先走 `SKILL.md` 工具链与 P0–P10。
